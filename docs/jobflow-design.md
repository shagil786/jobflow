# JobFlow Formal Design Specification

**Status:** Approved foundation / implementation slice  
**Date:** 2026-08-21  
**Scope:** Production-oriented core workflow; expansion modules gated

## Context

Job seekers lose recruiter conversations, forget follow-up timing, and cannot reliably connect applications, outreach, resumes, and outcomes. JobFlow turns a captured job and explicitly scoped Gmail conversation into a reviewable timeline and a next action.

The first release is private by default. It does not auto-apply, mass-send cold email, guess contact addresses, or treat AI extraction as accepted truth.

## Functional requirements

- FR-1: The system MUST support a private tenant-scoped workspace.
- FR-2: The browser capture flow MUST store URL, company, role, location, source, visible job data, and user corrections.
- FR-3: Gmail ingestion MUST process only the explicit `JobFlow/Track` label or an optional user search.
- FR-4: An application MUST require company, role, and user confirmation for identity.
- FR-5: The system MUST keep applications, email threads, messages, contacts, and timeline events separate.
- FR-6: AI MUST return a suggestion, confidence, evidence, and missing fields; it MUST NOT silently overwrite accepted data.
- FR-7: Follow-up dates MUST be generated by transparent rules and confirmed or changed by the user.
- FR-8: Draft generation MUST check recipient, duplicate outreach, thread, application status, resume selection, and unsupported claims.
- FR-9: Drafts MUST be editable and MUST NOT be sent automatically.
- FR-10: Referral profiles MUST be opt-in and reveal direct contact only after request acceptance.

## Non-functional requirements

- NFR-1: Every request and event MUST carry tenant ID, user ID, correlation ID, and idempotency key.
- NFR-2: Raw email bodies MUST NOT be written to application logs or traces.
- NFR-3: All important interactive UI states MUST support loading, empty, error, success, keyboard navigation, and narrow screens.
- NFR-4: Background work MUST support retries, dead-letter handling, and idempotent consumers.
- NFR-5: Resume files MUST remain private and be served only through short-lived access URLs.

## Acceptance criteria

- AC-1 (FR-2): Given a visible job page, when capture is submitted, then the normalized URL, title, company, role, location, source, and description preview are shown for correction.
- AC-2 (FR-6): Given an uncertain message, when classification completes, then the review queue shows status, confidence, evidence, and accept/edit actions.
- AC-3 (FR-7): Given an application without recent contact, when the rules run, then the user sees a suggested follow-up date and can accept, reschedule, or dismiss it.
- AC-4 (FR-8, FR-9): Given an eligible application, when draft generation runs, then an editable unsent draft is returned and no send operation occurs.
- AC-5 (FR-10): Given a referral request, when the employee has not accepted, then the candidate cannot see direct contact details.
- AC-6 (NFR-3): Given a 320px viewport, when the dashboard renders, then no horizontal page overflow occurs and primary actions remain reachable by keyboard.
- AC-7 (NFR-4): Given a duplicate event, when a consumer handles it twice, then the second handling produces no duplicate timeline record.

## Core interfaces

```ts
export type ApplicationStatus =
  | "captured" | "applied" | "outreach" | "follow_up"
  | "interview" | "rejected" | "offer" | "closed" | "unknown";

export interface ClassificationSuggestion {
  status: ApplicationStatus;
  company?: string;
  role?: string;
  applicationDate?: string;
  contact?: string;
  confidence: number;
  evidence: EvidenceSpan[];
  requiresReview: boolean;
}

export interface DraftRequest {
  applicationId: string;
  threadId?: string;
  resumeVersionId?: string;
  draftType: "follow_up" | "outreach" | "application";
  userInstructions?: string;
}
```

## Out of scope

Automatic applications, mass cold-email campaigns, automatic sending, private LinkedIn scraping, paid referrals, public profiles by default, full job-board search, Outlook integration, team workspaces, and uncalibrated automatic classification.
